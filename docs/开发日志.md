## 2. 关键决策记录

**ADR-1：规则引擎设计**
- 决策：规则以 YAML 声明，由 `rule_engine.py` 加载并执行 [source:readme:13, source-code:evaluator.py:15]。
- 理由：声明式规则与代码解耦，非开发人员可编辑。
- 后果：规则文件需手动维护，无法由数据自动反推规则。

**ADR-2：YAML + custom 混合规则**
- 决策：6 种内置规则覆盖常见场景，custom 类型通过 Python `evaluate()` 函数扩展 [source:readme:85-97]。
- 理由：YAML 表达力受限于内置规则，复杂业务逻辑需逃逸到 Python。
- 后果：custom 规则与项目代码强绑定，移植性弱于纯 YAML 规则。

**ADR-3：3 Sheet 报告格式**
- 决策：Excel 报告固定输出摘要、明细、失败记录三个 Sheet [source:readme:112-118]。
- 理由：分层呈现满足不同受众需求，摘要给管理者，明细给数据人员，失败记录给修复人员。
- 后果：报告布局固定，无法按场景裁剪 Sheet。

**ADR-4：GUI 与 CLI 双入口**
- 决策：`main.py` 默认启动 GUI，加 `--cli` 切换命令行模式 [source:source-code:main.py:5-8, 41-46]。
- 理由：GUI 便于非技术用户操作，CLI 便于脚本化与自动化。
- 后果：两条入口路径需各自维护参数解析与默认值，新增参数需同步两边。
