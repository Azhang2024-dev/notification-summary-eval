## 1. 项目概述

通知摘要评测工具是一个自动化评测脚本，基于规则文件对 CSV 或 Excel 数据集进行评测，并输出格式化的 Excel 报告 [source:readme:1-3]。

主要功能：
- 通过 YAML 规则文件定义评测逻辑，支持 6 种规则类型 [source:readme:55-64]
- 对数据集逐条记录执行规则检查，汇总通过率与失败明细 [source:readme:112-118]
- 输出包含 3 个 Sheet 的 Excel 报告，带颜色标记通过或失败状态 [source:readme:114-117]
- 支持自定义 Python 函数扩展规则逻辑 [source:readme:85-97]

## 2. 架构与目录结构

项目采用分层结构，按职责拆分核心模块 [source:readme:7-25]：

```
eval_project/
├── main.py                     # 主入口
├── requirements.txt
├── core/
│   ├── data_loader.py          # 数据加载（CSV / Excel → list[dict]）
│   ├── rule_engine.py          # 规则引擎（加载 YAML 规则并执行）
│   └── evaluator.py            # 评测器（串联加载 + 引擎 + 汇总）
├── utils/
│   ├── report_writer.py        # Excel 报告输出（3 个 Sheet）
│   └── logger.py               # 统一日志
├── rules/
│   ├── default_rules.yaml      # 示例规则文件
│   └── custom_score_check.py   # 自定义规则函数示例
├── data/
│   └── sample.csv              # 示例数据集
├── output/                     # 报告输出目录（自动创建）
└── logs/                       # 日志目录（自动创建）
```

关键分层约定：
- `core/` 承载数据加载、规则引擎、评测器三个核心环节，由 `evaluator.py` 串联 [source:source-code:evaluator.py:14-16]
- `utils/` 放置横切关注点（报告输出、日志），与业务逻辑隔离 [source:readme:15-17]
- `rules/` 同时存放 YAML 规则与 Python 自定义函数，规则与代码同目录便于引用 [source:readme:18-20]
- `output/` 与 `logs/` 由程序自动创建，无需预置 [source:readme:23-24]

## 3. 技术策略与关键决策

**决策 1：YAML 规则引擎**
规则以 YAML 文件声明，位于 `rules/` 目录 [source:readme:55]。理由：声明式规则便于非开发人员修改，规则文件可独立版本管理。后果：规则文件需手动编写，无法自动生成。

**决策 2：6 种规则类型**
内置 `not_empty`、`regex`、`length`、`contains`、`not_contains`、`custom` 六种规则类型 [source:readme:57-64]。理由：覆盖常见数据质量检查场景，custom 类型保留扩展能力。后果：超出这 6 种的检查需求必须通过 custom Python 函数实现。

**决策 3：custom 规则支持 Python 函数**
在 `rules/` 目录创建 `<func_module>.py`，实现 `evaluate(value, record, rule) -> tuple[bool, str]` 接口，YAML 中以 `func_module` 字段引用 [source:readme:85-107]。理由：纯 YAML 表达力有限，custom 类型允许在数据驱动检查之外嵌入复杂业务逻辑。

**决策 4：Excel 报告 3 Sheet 带颜色标记**
报告输出为 Excel，包含摘要、明细、失败记录三个 Sheet [source:readme:112-117]。明细 Sheet 用绿色表示通过、红色表示失败 [source:readme:117]。理由：颜色标记让通过或失败状态一眼可辨，摘要与失败记录分离便于不同受众阅读。

**决策 5：severity 分级**
规则支持 `error` 与 `warning` 两种严重级别 [source:readme:74]。`error` 计入失败记录，`warning` 仅作提示 [source:readme:74]。理由：区分硬性约束与软性建议，避免 warning 噪声污染失败统计。

## 5. 运行与验证

启动方式 [source:readme:27-51]：

```bash

python main.py

# 指定数据、规则、输出
python main.py --cli --data data/my_dataset.xlsx --rule rules/my_rules.yaml --output output/result.xlsx

# 查看所有参数
python main.py --help
```

3. 检查 `output/` 目录生成的 Excel 报告，确认 3 个 Sheet 与颜色标记 [source:readme:112-118]

## 6. 已知限制与风险

基于 README 推断的限制：

- **规则文件需手动编写**：YAML 规则不能自动生成，新增检查需求需开发者编辑规则文件 [source:readme:55, inference]。
- **无 LLM 评分**：核心评测为纯规则检查，README 未提及 LLM 自动评分集成。`.gui_settings.json` 配置了 LLM 模型，但 README 描述的运行流程未将其纳入 [source:readme:55-64, gui-settings:13-101]。
- **报告格式固定**：3 Sheet 结构与颜色标记由 `report_writer.py` 固化，用户无法自定义 Sheet 布局 [source:readme:112-118]。
- **目录名沿用 eval_project**：README 项目结构仍写作 `eval_project/`，但 `.claude/settings.local.json` 显示项目实际迁移到 `eval_project_v1.0` 目录 [source:readme:8, claude-settings:8-17]。文档与实际目录名存在不一致。
